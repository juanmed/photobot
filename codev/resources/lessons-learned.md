## Testing

### Import location matters for `unittest.mock.patch`

`patch("module.ClassName")` only works when `ClassName` is a module-level
attribute of `module`. If imported inside a function, `patch` raises
`AttributeError`. Always import hardware/external dependencies at module level
with a `try/except ImportError` fallback when the dependency may not be
available on all platforms.

```python
# Correct — patchable
try:
    from rpi_hardware_pwm import HardwarePWM
except ImportError:
    HardwarePWM = None

# Wrong — patch("sw.pwm_controller.HardwarePWM") fails
def start(self):
    from rpi_hardware_pwm import HardwarePWM  # NOT patchable
```

### Mock instance dict populated lazily after `start()`

When a mock fixture collects instances keyed by a hardware parameter (e.g.,
`instances[pwm_channel]`), entries only exist after the code under test calls
the constructor. Always call `ctrl.start()` (or equivalent) before accessing
`instances[key]` in test setup — or the test will get `KeyError`.

### Avoid delegating in `side_effect` back to the same mock

Saving `original = mock.method` and then calling `original(val)` inside a
`side_effect` causes infinite recursion because `original` IS the mock — it
will invoke the side_effect again. Instead, record the observation and return
directly without calling through.

```python
# Wrong — infinite recursion
original = instances[0].change_duty_cycle
def tracker(val):
    log.append(val)
    return original(val)  # calls tracker again → RecursionError

# Correct — no delegation needed
def tracker(val):
    log.append(val)
    # mock returns MagicMock() by default, which is fine
```

## Process

### Gemini consultation availability

`gemini-3-pro-preview` is subject to capacity exhaustion (HTTP 429
MODEL_CAPACITY_EXHAUSTED). When Gemini fails across multiple phases, notify
the architect early and get explicit approval to proceed with 2/3 models
(Claude + Codex) rather than retrying indefinitely.

### Consultation catches real omissions

The 3-way consultation pattern reliably surfaced missing behaviors across all
5 phases of this project. Don't skip consultation, even when the code seems
obviously correct — a second perspective catches things the author misses.
